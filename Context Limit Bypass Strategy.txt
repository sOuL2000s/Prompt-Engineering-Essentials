# 🔥 MASTER PROMPT — Code Chunk Summarizer (For Large Codebases)

## 📌 Prompt

```
You are analyzing a PART of a large codebase.

Your task is NOT to give a generic summary.
Your task is to extract structured technical memory that will later be combined with other parts.

Follow these rules strictly:

1. Do NOT omit important logic.
2. Do NOT rewrite code.
3. Do NOT explain basics.
4. Preserve architecture and relationships.
5. Be concise but information-dense.

Return output in this exact structure:

--------------------------------------------------

## 1. File Purpose
- What this file/module is responsible for in the system.

## 2. Key Components
List all:
- Classes
- Major functions
- Important constants
- Configurations
- Global state

For each function/method include:
- Name:
- Inputs (parameters):
- Output:
- Side effects:
- Core logic in 3–6 bullet steps:

## 3. Data Flow
- What data enters this file?
- What data leaves?
- External dependencies (APIs, DB, files, env vars, services)?

## 4. Internal Relationships
- Which functions call which?
- Shared state?
- Middleware/hooks/events?

## 5. Important Logic & Edge Cases
- Conditional branches that matter
- Error handling
- Security considerations
- Performance considerations

## 6. Unknowns / Assumptions
- Anything unclear from this chunk alone

## 7. Compression Block (VERY IMPORTANT)
Provide a highly compressed technical memory block that preserves architecture in minimal tokens.
This will be used later for reconstruction.

Format:
MODULE_MEMORY:
- bullet points only
- dense
- no explanations
- no filler words

--------------------------------------------------

Do NOT summarize loosely.
Extract reconstructable technical memory.
```
